# API application

Node.js, Express, TypeScript, Zod, Prisma, and PostgreSQL.

## Responsibilities

- Expose versioned HTTP endpoints under `/api/v1`.
- Validate request payloads at the boundary.
- Keep persistence behind the task repository interface.
- Return consistent client-safe error responses.
- Keep the health endpoint independent of database credentials.

## Task endpoints

- `GET /api/v1/tasks` — list tasks; supports `status` and `priority` filters.
- `POST /api/v1/tasks` — create a task.
- `GET /api/v1/tasks/:id` — retrieve one task.
- `PATCH /api/v1/tasks/:id` — update task fields.
- `DELETE /api/v1/tasks/:id` — delete a task after explicit user action.

All request bodies are validated with Zod. Unknown fields are rejected.

## Local database

Configure `DATABASE_URL` in the repository root `.env`, then run:

```bash
docker compose up -d postgres
npm run db:generate
npm run db:migrate
```

The Prisma schema is in `prisma/schema.prisma`. Migration files are generated by Prisma when the local database is available.

## Tests

Route tests use an in-memory repository, so they do not require a running PostgreSQL instance. Production persistence uses `PrismaTaskRepository`.
